01 / Problem framing

Detection alone is not the whole application.

A model can identify people in individual frames, but a useful monitoring tool needs more context: whether detections persist across frames, how tracked objects move, when entry or exit events occur, and how the results are communicated to an operator.

VisionSense-AI was built as an end-to-end portfolio project to connect these pieces into one demonstrable system.

02 / System design

From video frames to session intelligence.

Person detection

A custom-trained YOLO11n model detects people in the video stream.

Multi-object tracking

ByteTrack maintains tracker IDs across frames. These IDs represent tracked objects, not verified real-world identities.

Movement and events

Application logic estimates movement state and direction, and derives entry/exit events from tracked movement.

API and dashboard

FastAPI exposes status, analytics, event history, a processed video feed, and WebSocket event updates to the Next.js dashboard.

03 / Model evaluation

Report the evaluation with its limits.

The custom-trained YOLO11n person detector was trained for 50 epochs at 640×640 image size using a batch size of 16 on an NVIDIA Tesla T4. The project README records the following held-out test metrics:

57.8%Test mAP50
34.5%Test mAP50–95

These are project-specific test results, not a guarantee of accuracy in every environment. Performance can vary with lighting, camera angle, crowd density, and similarity to the training data.

Training configuration, checkpoints, evaluation curves, confusion matrices, and other experiment artifacts are maintained in the Person-Dataset repository.

04 / Stack

Engineering across the full pipeline

  • Computer vision: Python, OpenCV, Ultralytics YOLO11n, ByteTrack
  • Backend: FastAPI, Uvicorn, REST endpoints, WebSockets, CSV event logging
  • Frontend: Next.js, React, TypeScript, Tailwind CSS
  • Deployment: Vercel for the dashboard; Render for the API

05 / Demo and limitations

Demonstrable, with boundaries stated clearly.

The hosted dashboard uses a prerecorded demo video rather than a visitor's webcam. The project also supports local camera mode when run in the intended local environment.

  • Movement and direction are estimates based on tracked bounding-box motion.
  • Tracker IDs should not be treated as confirmed identities.
  • The free cloud deployment is intended for demonstration and may have resource or performance limits.
  • The evaluation metrics should be interpreted in the context of the project's test set.

06 / What this demonstrates

More than a model notebook.

VisionSense-AI demonstrates an end-to-end engineering workflow: preparing a dataset, training and evaluating a detector, integrating tracking and deterministic event logic, exposing results through an API, building a browser dashboard, and deploying the system for demonstration.
